# 账号 × 模型定时检测方案

PoolGuard 以账号的检测模型清单为范围，每轮执行“每个监测账号的每个配置模型 × 全部启用题目”，按账号汇总后执行启停。可按账号拉取 CPR 上游模型目录，勾选保存后纳入定时计划；目录中的模型是否实际可用仍以答题结果为准。

## 前端配置

1. 在账号池同步账号。
2. 对每个账号点击“拉取上游模型”，成功后可在“复检范围”直接选择返回的模型。进入“配置检测模型”勾选需要定时检测的模型并保存，也可以手动填写 ID。最多 20 个，允许不同账号使用不同清单；拉取目录或同步账号不会覆盖已保存的定时清单。尚未配置的账号沿用项目默认模型。
3. 在检测策略中启用明确、简短且能稳定判分的题目。建议先使用 1–2 道题，避免要求长篇证明导致超时。模糊匹配仍是文本匹配，不能判断论证语义。
4. 在系统设置保存检测间隔。建议先从 30 分钟开始，根据检测记录的整轮耗时调整；现有间隔不会被升级覆盖。恢复次数按现有设置执行。
5. 账号池和系统设置显示计划摘要。先点击“立即检测”验证所有配置模型，再由定时调度持续执行。单账号“复检范围”可选全部模型或指定模型。

每轮答题数为 `所有监测账号的模型数量之和 × 启用题目数`。例如账号 A 配置 3 个模型，账号 B 配置 2 个模型，启用 2 道题，一轮共 10 次调用。同步时新出现的账号会影响实际数量，页面摘要为当前目录估算。

## 每轮执行

1. 调度器每 30 秒检查一次到期时间，获取全局任务锁；上一轮未完成时顺延，不叠加批次。
2. 固定本轮题目快照，同步远端账号目录。只有成功同步项目中的有效监测账号进入本轮。自动隔离账号继续监测；人工停用或控制冲突后暂停监测的账号不自动恢复。
3. 计算本轮 `plannedChecks`，逐账号检查隔离回执，再依次遍历该账号的配置模型和启用题目。
4. 对 CPR 调用 `POST /api/admin/accounts/poolguard/probe`，请求包含 `accountId`、当前 `model` 和题目 `prompt`。使用管理员凭据，不发送标准答案，不回退到其他账号。
5. 每次调用独立保存账号、模型、题目、判分方式、结果、回答和耗时；`completedChecks` 随记录写入而增加。超时、502、不支持的模型等普通接口异常记为 ERROR，继续下一道题和后续模型，不重试同一项以免隐性扩大开销。
6. 某账号的全部组合执行完后，再按下表决定是否调用现有控制接口。之后继续下一个账号。

| 该账号本轮结果 | 动作 |
| --- | --- |
| 有 ERROR，不论是否也有答错 | 保持启停状态，清零连续判断次数，下轮重测 |
| 无 ERROR，至少一道题答错 | 按失败阈值禁用整个账号；默认 1 轮，手动复检始终 1 轮 |
| 全部配置模型、全部题目通过 | 已启用账号保持启用；自动隔离账号累计恢复次数，达到阈值后恢复 |
| 只手动检测了部分模型且通过 | 保持启停状态，不累计全模型恢复次数 |

CPR 控制仍作用于整个账号，不支持只禁用某个模型。自动控制继续使用隔离操作回执、控制版本和幂等操作 ID。

控制版本冲突会停止该账号剩余检测并暂停自动管控；其他账号继续。任务锁丢失、数据库故障或进程中断会终止批次，不承诺在这些条件下继续发送请求。计划数量保留，完成数量小于计划数量时界面提示“未完整执行”。同步失败项目的原因显示在批次异常中，不能将未同步账号视为已检测。

## 验证与追溯

- `GET /api/detection-runs/latest` 或 `/api/detection-runs/search`：查看 `triggerType=SCHEDULED`、`plannedChecks`、`completedChecks`、账号级通过/答错/异常数量及总耗时。
- `GET /api/detection-runs/{id}/results`：查看每条记录的 `accountId`、`model`、`policyId`、`outcome`、`latencyMs`。
- 完成数量表示已记录调用结果，包含 ERROR，不表示全部通过。旧批次无可靠的模型计划快照，两个数量返回 null，界面显示“未记录”。
- `POST /api/accounts/{id}/models/sync` 拉取账号目录，响应 `upstreamModels` / `modelsSyncedAt`，刷新页面后仍可选择；上游刷新失败保留旧目录。
- `PUT /api/accounts/{id}/models` 保存 `{"models":["实际模型ID一","实际模型ID二"]}`；`POST /api/accounts/{id}/actions` 使用 `{"action":"retest"}` 检测全部定时配置模型，增加 `model` 可指定已配置或从上游拉取的一个模型。

`ScheduledCoverageTest` 验证两个账号、两个模型、两道题的 8 项组合完整覆盖；首项异常不会遗漏后续题目和模型；同一时间只执行一个批次；自动隔离账号下轮全通过后恢复；控制版本冲突保留未完成进度。
